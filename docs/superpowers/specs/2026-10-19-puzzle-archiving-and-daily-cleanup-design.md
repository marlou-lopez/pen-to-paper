# Design Specification: Puzzle Archiving & Daily Stale Cleanup System

**Date:** 2026-10-19  
**Status:** Approved  
**Author:** Pair Programming Assistant & User

---

## 1. Executive Summary
As puzzles are generated and delivered daily to the reMarkable tablet, `/Puzzles/Daily` accumulates tens of documents over time. Additionally, when a user completes a puzzle on their tablet, they mark it with the tag `DONE` (or prefix `[DONE]`). Currently, there is no automated mechanism to move completed puzzles to the archive or sweep uncompleted older daily puzzles out of the `/Puzzles/Daily` folder into their respective category folders.

This feature introduces an automated lifecycle management system:
1. **Archive Completed Puzzles**: Detects any puzzle under `/Puzzles` tagged with `DONE` (case-insensitive: `DONE`, `Done`, `done`) or titled with `[DONE] ...`, and moves it to its category-specific archive subfolder (`/Puzzles/Archive/<Category>/`).
2. **Sweep Stale Dailies**: Scans uncompleted puzzles in `/Puzzles/Daily`. Any puzzle whose filename date is older than 2 days (i.e. older than yesterday) is moved out of `/Puzzles/Daily` into its category folder (`/Puzzles/<Category>/`), keeping the Daily folder fresh and clutter-free.
3. **Execution Modes**: Available as a reusable TypeScript module (`cleanupPuzzles()`), an npm CLI command (`npm run cleanup`), a dedicated GitHub Action workflow (`.github/workflows/cleanup-puzzles.yml`), and an automated pre-step in the daily generation workflow (`.github/workflows/daily-puzzles.yml`).

## 2. Puzzle Identification & Categorization Rules

### 2.1 Category Mapping
All puzzles generated by the system adhere to deterministic filename prefixes:
- `WordSearch_...` $\rightarrow$ `'Word Search'` $\rightarrow$ Category Folder: `/Puzzles/Word Search`, Archive Folder: `/Puzzles/Archive/Word Search`
- `Sudoku_...` $\rightarrow$ `'Sudoku'` $\rightarrow$ Category Folder: `/Puzzles/Sudoku`, Archive Folder: `/Puzzles/Archive/Sudoku`
- `MiniCrossword_...` $\rightarrow$ `'Mini Crossword'` $\rightarrow$ Category Folder: `/Puzzles/Mini Crossword`, Archive Folder: `/Puzzles/Archive/Mini Crossword`
- `KenKen_...` $\rightarrow$ `'KenKen'` $\rightarrow$ Category Folder: `/Puzzles/KenKen`, Archive Folder: `/Puzzles/Archive/KenKen`
- `Kakuro_...` $\rightarrow$ `'Kakuro'` $\rightarrow$ Category Folder: `/Puzzles/Kakuro`, Archive Folder: `/Puzzles/Archive/Kakuro`
- `Futoshiki_...` $\rightarrow$ `'Futoshiki'` $\rightarrow$ Category Folder: `/Puzzles/Futoshiki`, Archive Folder: `/Puzzles/Archive/Futoshiki`

If a file has a `[DONE]` prefix in its title (e.g. `[DONE] MiniCrossword_2026-10-13`), the prefix is stripped when matching the puzzle type. If a file cannot be categorized, it falls back to `'Other'` (`/Puzzles/Archive/Other`).

### 2.2 Completion Detection (`isCompleted`)
A document is classified as completed if:
1. Any tag in its metadata matches `/^done$/i` (matches `'DONE'`, `'done'`, `'Done'`), OR
2. The document name starts with `[DONE]` (case-insensitive, e.g. `[DONE] MiniCrossword_2026-10-13`).

### 2.3 Stale Date Calculation (`isStaleDaily`)
- Puzzle filenames embed the puzzle generation date in `YYYY-MM-DD` format (e.g. `Sudoku_Medium_2026-10-13`, `WordSearch_2026-10-18_Botany`).
- The date string is extracted using regex `/\b(\d{4}-\d{2}-\d{2})\b/`.
- Date difference is computed in whole calendar days relative to UTC today (or an optionally passed reference date for deterministic testing):
  $$\Delta \text{days} = \lfloor (\text{todayUtcMs} - \text{puzzleUtcMs}) / 86,400,000 \rfloor$$
- A puzzle in `/Puzzles/Daily` is stale if:
  $$\Delta \text{days} \ge \text{retentionDays}\quad (\text{default: } 2)$$
  and it is **not** already completed.

## 3. Architecture & Interfaces

### 3.1 Delivery Client Extensions (`src/delivery/types.ts`)
We extend the client interface with document listing and moving operations:

```typescript
export interface RemoteDocument {
  id?: string;
  name: string;        // e.g. "Sudoku_Medium_2026-10-13" or "[DONE] MiniCrossword_2026-10-13"
  path: string;        // e.g. "/Puzzles/Daily/Sudoku_Medium_2026-10-13"
  folder: string;      // e.g. "/Puzzles/Daily"
  tags: string[];      // e.g. ["DONE"]
}

export interface CleanupClient extends DeliveryClient {
  listDocuments(folder: string, recursive?: boolean): Promise<RemoteDocument[]>;
  moveDocument(sourcePath: string, destinationFolder: string): Promise<void>;
}
```

### 3.2 `RmapiDeliveryClient` Implementation (`src/delivery/rmapi-client.ts`)
- **`listDocuments(folder, recursive)`**:
  - Executes `rmapi -json find <folder>` for recursive listing, or `rmapi -json ls <folder>` for single folder.
  - Parses the JSON output array of document items (`id`, `name`, `type`, `parent`, `tags`).
  - Constructs the full canonical path `/Puzzles/.../<name>` for each entry.
- **`moveDocument(sourcePath, destinationFolder)`**:
  - Ensures destination folder exists via `ensureFolder(destinationFolder)`.
  - Executes `rmapi mv "<sourcePath>" "<destinationFolder>"` with retry & backoff logic (`maxRetries: 3`, exponential backoff).

### 3.3 `LocalDeliveryClient` Implementation (`src/delivery/local-client.ts`)
- Implements directory listing and moving (`fs.rename`) in the local output directory for offline development and testing.

### 3.4 Cleanup Engine (`src/delivery/cleanup.ts`)
```typescript
export interface CleanupOptions {
  client: CleanupClient;
  retentionDays?: number; // default: 2
  dryRun?: boolean;       // default: false
  referenceDate?: string; // YYYY-MM-DD for deterministic testing
}

export interface MoveAction {
  name: string;
  from: string;
  to: string;
}

export interface CleanupSummary {
  archived: MoveAction[];
  staleMoved: MoveAction[];
  skipped: { name: string; reason: string }[];
}

export async function cleanupPuzzles(options: CleanupOptions): Promise<CleanupSummary>;
```

#### Cleanup Execution Flow:
1. **Pass 1: Archiving Completed Puzzles**:
   - Query all documents under `/Puzzles` recursively.
   - Filter documents where `isCompleted(doc) === true` and `doc.folder` does **not** already start with `/Puzzles/Archive`.
   - Determine destination archive folder: `/Puzzles/Archive/<Category>`.
   - If `dryRun` is false, invoke `client.moveDocument(doc.path, destFolder)`.
   - Record in `summary.archived`.
2. **Pass 2: Sweeping Stale Dailies**:
   - Query all documents directly in `/Puzzles/Daily`.
   - Filter documents where `isCompleted(doc) === false` and `isStaleDaily(doc.name, retentionDays, referenceDate) === true`.
   - Determine destination category folder: `/Puzzles/<Category>`.
   - If `dryRun` is false, invoke `client.moveDocument(doc.path, destFolder)`.
   - Record in `summary.staleMoved`.
3. Log clean summary to console with counts and paths.

## 4. CLI Integration (`src/cli.ts`)

### 4.1 Usage
```bash
# Dry run preview (logs actions without moving)
npm run cleanup -- --dry-run

# Run cleanup on remote reMarkable tablet (2 days retention)
npm run cleanup -- --upload --days=2

# Run cleanup on local output directory
npm run cleanup -- --local --days=2
```

### 4.2 Options
- `--days=<number>`: Daily retention threshold in days (default: 2, min: 1).
- `--dry-run`: Simulation mode.
- `--upload`: Use `RmapiDeliveryClient` to clean up reMarkable Cloud.
- `--local`: Clean up local filesystem output directory (default if `--upload` not supplied).

## 5. GitHub Actions Workflows

### 5.1 Standalone Cleanup Workflow (`.github/workflows/cleanup-puzzles.yml`)
```yaml
name: Tidy & Archive reMarkable Puzzles

on:
  schedule:
    # Runs at 20:00 UTC (1 hour before 21:00 UTC daily puzzle generation)
    - cron: '0 20 * * *'
  workflow_dispatch:
    inputs:
      retention_days:
        description: 'Days before uncompleted dailies move to category folder'
        required: false
        default: '2'
        type: string
      dry_run:
        description: 'Dry run mode (preview without moving files)'
        required: false
        default: false
        type: boolean

jobs:
  cleanup:
    runs-on: ubuntu-latest
    env:
      RMAPI_AUTH_TOKEN: ${{ secrets.RMAPI_AUTH_TOKEN }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
      - run: npm ci
      - name: Install rmapi
        run: |
          mkdir -p $HOME/bin
          curl -L -s https://github.com/ddvk/rmapi/releases/download/v0.0.35/rmapi-linux-amd64.tar.gz | tar xz -C $HOME/bin
          chmod +x $HOME/bin/rmapi
          echo "$HOME/bin" >> $GITHUB_PATH
      - name: Setup rmapi auth
        run: |
          mkdir -p ~/.config/rmapi
          echo "$RMAPI_AUTH_TOKEN" > ~/.rmapi
          echo "$RMAPI_AUTH_TOKEN" > ~/.config/rmapi/rmapi.conf
      - name: Run cleanup
        run: |
          DRY_RUN_FLAG=""
          if [ "${{ inputs.dry_run }}" = "true" ]; then
            DRY_RUN_FLAG="--dry-run"
          fi
          npm run cleanup -- --upload --days=${{ inputs.retention_days || 2 }} $DRY_RUN_FLAG
```

### 5.2 Daily Generation Pre-Step (`.github/workflows/daily-puzzles.yml`)
Add an automated cleanup step directly before `npm run generate`:
```yaml
      - name: Tidy completed and stale puzzles
        run: npm run cleanup -- --upload --days=2
```

## 6. Testing Strategy

1. **Unit Tests (`tests/delivery/cleanup.test.ts`)**:
   - Categorization helper tests across all 6 puzzle types + unknown fallback.
   - Completion detection tests (`DONE`, `done`, `Done`, `[DONE] ...`, untagged).
   - Date extraction and stale calculation tests with known reference dates.
   - Full orchestration test with a Mock `CleanupClient`:
     - Verifies completed files in `/Puzzles/Daily` and `/Puzzles/<Category>` are archived.
     - Verifies files already in `/Puzzles/Archive` are skipped.
     - Verifies stale files $> 2$ days are moved to category folders.
     - Verifies recent files $\le 2$ days are kept in `/Puzzles/Daily`.
     - Verifies `dryRun` performs no `moveDocument` calls.
2. **Client Unit Tests (`tests/delivery/rmapi-client.test.ts`)**:
   - Tests `listDocuments` JSON parsing from `rmapi` command output.
   - Tests `moveDocument` command invocation with retry/backoff.
3. **CLI Argument Tests (`tests/cli.test.ts`)**:
   - Tests `--cleanup`, `--days`, `--dry-run` flag parsing.
